Under the hood

BMAD turns one idea into a chain of teachable artifacts.

  • Research brief, PRD, architecture, and UI/UX documents establish the operating context.
  • Epics and user stories split the work into reviewable implementation chunks.
  • Implementation cycles, quick-dev flow, brownfield documentation, and testing loops keep the work from drifting.
  • MCP and reporting integrations make progress visible outside the chat window.

Reporting

Make the development loop observable.

The lab should show how a team can expose status, assignments, artifacts, and work items through the tools it already uses. That turns BMAD from a local prompt convention into a team development system.

Execution model

Set expectations for real production work.

Planning and architecture

Team infrastructure
