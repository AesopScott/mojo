Lesson 01

What did installing Pi actually do?

Pi was installed as a global npm package. That means npm placed a small command shim on your PATH, and that shim launches Pi's CLI code from the global npm package folder.

Windows example

Where Pi installs globally

On Scott's Windows machine, PowerShell finds the Pi command here: 

C:\Users\scott\AppData\Roaming\npm\pi.ps1

The installed package code lives here: 

C:\Users\scott\AppData\Roaming\npm\node_modules\@earendil-works\pi-coding-agent

The command shim ultimately launches: 

...\@earendil-works\pi-coding-agent\dist\cli.js
Try it yourself

Commands that reveal the install

Use these from PowerShell to see where your own copy is installed.

Get-Command pi
npm root -g
npm prefix -g
npm list -g @earendil-works/pi-coding-agent --depth=0

Useful mental model: npm installed a released package. It is not a fork or live source checkout, so updates arrive only when you update Pi.

Configuration

Where Pi keeps your settings and login state.

Pi separates the installed program from your personal settings, cached model lists, credentials, sessions, and project trust decisions.

Global Pi folder ~/.pi/agent

On Windows: C:\Users\scott\.pi\agent

Settings ~/.pi/agent/settings.json

Stores defaults such as theme, default provider, and default model.

Authentication ~/.pi/agent/auth.json

Stores OAuth tokens or API-key credentials. Do not share this file.

Model cache ~/.pi/agent/models-store.json

Caches provider model catalogs so Pi can show available models.

Sessions ~/.pi/agent/sessions/

Stores saved Pi conversations and session history.

Project trust ~/.pi/agent/trust.json

Appears after saving trust decisions with /trust.

Project-specific configuration

A project can also contain .pi/settings.json and other .pi resources. Pi asks about project trust before loading those resources, but project trust is not a sandbox.

Authentication

Two ways Pi connects to model providers.

Pi does not require a separate Pi account in the normal beginner flow. Instead, it authenticates with providers that can serve models.

Method 1

Subscription or OAuth login

Start Pi, run /login, and choose a provider. This can open a browser authorization flow. OpenRouter's authorization flow signs you in and creates provider credentials for Pi to use. 

pi
/login openrouter

Pi's built-in subscription-style login options include ChatGPT Plus/Pro through Codex, Claude Pro/Max, GitHub Copilot, xAI, OpenRouter, and Radius.

Method 2

API-key authentication

An API key is a secret token from a provider. You can set it as an environment variable before launching Pi, or enter it through /login so Pi stores it in auth.json. 

$env:OPENROUTER_API_KEY="your-openrouter-key"
pi --provider openrouter

Other common provider variables include OPENAI_API_KEY, ANTHROPIC_API_KEY, and GEMINI_API_KEY.

What "logged in" means

If Pi says you are logged into OpenRouter, Pi has credentials it can use to request models through your OpenRouter account. The next step is choosing a model with /model.

Safety note

Tool access is the real permission boundary.

By default, Pi can use tools such as read, write, edit, and bash. If you want a read-only learning session, start Pi with only read tools enabled. 

pi --tools read,grep,find,ls
pi --exclude-tools bash
